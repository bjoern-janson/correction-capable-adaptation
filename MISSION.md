# Mission

## One project

**Correction-Capable Adaptation** is one research program with one central scientific question:

> **Can an adaptive system increase its future viability while remaining capable of incorporating justified correction?**

Everything else in this repository is a theory layer, methodological instrument, measurement problem, mechanism, experiment, ancestral result, or downstream stress test within that program.

## One sentence

> **Build a scientific framework for understanding whether adaptive systems can become more capable and viable while preserving their capacity to incorporate justified correction.**

## Scientific object

The object is not improvement alone. It is the capacity for **justified, validated transformation that preserves the capacity for further correction**.

Operationally:

\[
\boxed{
\textbf{Increase the capacity for justified transformation without destroying the capacity for further correction.}
}
\]

The deepest compression is:

\[
\boxed{\textbf{Preserve the ability to become appropriately different.}}
\]

## Causal pathway

The program studies the pathway:

\[
\boxed{
\text{Evidence}
\rightarrow
\text{Authority}
\rightarrow
\text{Warranted selection}
\rightarrow
\text{Effective modification}
\rightarrow
\text{Protected structure preserved}
\rightarrow
\text{Capability change}
\rightarrow
\text{Repeated correction}
\rightarrow
\text{Justified transformability}
\rightarrow
\text{Adaptive viability}
}
\]

Each arrow is a separate causal burden.

The project therefore keeps explicit:

```text
generated change       ≠ warranted change
warranted selection    ≠ effective modification
effective modification ≠ isolated modification
isolated modification  ≠ capability improvement
capability improvement ≠ adaptive viability
```

## Core methodological principle

> **Never infer a downstream capability from an unvalidated upstream mechanism.**

A failed upstream gate blocks downstream authority. A strong downstream outcome cannot compensate for an unidentified measurement object, evidence-insensitive selection, ineffective modification, or unacceptable protected interference.

## Theory, method, and experiments

The named components of the program have specific roles:

```text
CARS
→ methodological operating system for correction and scientific revision

Measurement layer
→ determines what evidence/correction can actually be identified

ECIM
→ provisional mechanism architecture for evidence-controlled isolated modification

MAGIKARP / justified transformability
→ provisional theory of what makes adaptive transformations better or worse

C_improve
→ program-level hypothesis connecting valid feedback and justified transformation to future viability

Capability / viability experiments
→ downstream consequences only after upstream mechanisms are established

ASI
→ possible extreme-capability stress-test regime, not the foundational object
```

None of these is an independent project.

## What this project is not

This repository does not begin from the assumption that:

- intelligence requires a special architectural primitive;
- self-modification is inherently beneficial;
- more capability implies more corrigibility;
- a successful output proves the system understood why it succeeded;
- viability follows from capability growth;
- ASI is imminent, inevitable, or already measured here.

ASI is treated only as a possible future **stress-test regime** if the upstream scientific gates are ever earned.

## Research-state commitment

The program preserves negative results, failed constructions, measurement impossibility boundaries, and unresolved forks.

A result earns only the authority its measurement and causal design identify.

Every empirical object follows the research state machine in [`methodology/RESEARCH_STATE_MACHINE.md`](methodology/RESEARCH_STATE_MACHINE.md), and the current authorization state is recorded in [`research_state.json`](research_state.json).
